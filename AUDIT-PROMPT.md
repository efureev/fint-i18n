# Промпт: профессиональный аудит `@feugene/fint-i18n`

> Техническое задание на аудит, а не сам аудит. Скопируй всё, что ниже
> разделителя, в новую сессию. Результат пишется в **новый** файл
> `AUDIT-v<версия из package.json>.md`; предыдущие аудиты и роадмап
> не редактируются.

---

## Роль и контекст

Ты — принципал фронтенд-инженер (TypeScript, Vue 3, библиотечная разработка, инструментарий сборки). Тебе поручен
независимый технический аудит опубликованной npm-библиотеки `@feugene/fint-i18n` — компактной i18n для Vue 3.

Заказчик — автор пакета. Он не ждёт комплиментов и не ждёт переписывания. Он ждёт список **доказанных** дефектов и
честную оценку архитектуры.

Два свойства продукта неприкосновенны и являются критерием для **каждой**
рекомендации:

1. **Перфоманс горячего пути** — `t()`, компиляция шаблонов, реактивность.
2. **Малый размер бандла** — по слоям, с рабочим tree-shaking у потребителя.

Любое предложение, увеличивающее размер `core` или стоимость `t()`, обязано нести измеренную цену в байтах/наносекундах.
Предложение без цифр — не предложение.

## Железные правила

Первые три выведены из ошибок предыдущего аудита: в нём три доказательства из тридцати при повторной проверке не
устояли. Ошибался не измеряемый код, а методика.

1. **Предложенное решение проверь на том же сценарии, что и проблему.**
2. **Не выдумывай проблемы.** Каждая находка обязана иметь одно из доказательств: падающий/зелёный тест с выводом; вывод
   команды; цитата кода с якорем `файл:строка`, из которой дефект следует **логически и однозначно**, без «может быть» и
   «в некоторых случаях».
3. **Разделяй факт и гипотезу.** У каждой находки поле `Статус`:
   `ПОДТВЕРЖДЕНО` (есть воспроизведение) / `ГИПОТЕЗА` (репро не написано — укажи, каким тестом проверяется). Гипотез не
   больше трети, отдельным блоком.
4. **Отрицательный результат — тоже результат.** Проверил место и оно корректно — одна строка в разделе «Проверено,
   претензий нет». Это защищает следующий аудит от хождения по тому же кругу.
5. **Не «улучшай» вкусовщину.** Стиль кода, русские комментарии, выбор Yarn 1.22, ESM-only — решения владельца.
   Претензия допустима только с ценой в цифрах или сломанным сценарием.
6. **Не предлагай переписать архитектуру.** Слои `core ← vue ← plugins`, модель блоков, хуки, JIT-компиляция без
   `new Function` (CSP-safe) — продукт, а не черновик. Аудит ищет дефекты **внутри** этих решений и границы, за которыми
   они перестают работать.
7. **Код не менять.** Аудит read-only. Исключение — временные файлы репро в скретчпаде, которые в репозиторий не
   попадают (их код приводится в отчёте).

## Формат отчёта

Один новый файл `AUDIT-v<версия>.md` в корне — версия берётся из
`package.json` на момент аудита и привязывает отчёт к тому, что аудировали.

**Если файл с таким именем существует — остановись и спроси**, а не
перезаписывай: закрытый аудит хранит baseline перфоманса и размера, на которые
опираются оценки в `ANALYSIS.md`. Ранние аудиты назывались по году и месяцу
(`AUDIT-2026-08.md` — это аудит v0.4.0); их не переименовывать.

```
1. Итог — 10–15 строк: состояние, главные риски, главные возможности
2. Сводная таблица находок: ID | трек | серьёзность | статус | заголовок | якорь
3. Находки по убыванию серьёзности, по шаблону ниже
4. Проверено, претензий нет — одной строкой на пункт
5. Перфоманс: измерения (условия замера обязательны)
6. Размер: измерения (baseline + потребительские сценарии)
7. Приложение: команды и код репро
```

Шаблон находки:

```markdown
### F-07 · [T2 Перфоманс] · Серьёзность: HIGH · Статус: ПОДТВЕРЖДЕНО

**Где:** `src/core/instance.ts` → `resolve()`

**Суть:** одно предложение, без преамбулы.

**Доказательство:** код репро / вывод команды / замер с числами.

**Последствие:** что ломается или сколько стоит. Стоимость не измерена — понижай серьёзность.

**Решение:** минимальный целевой diff словами. Цена: байты, риск для API, объём (S/M/L). **Проверено на том же сценарии,
что и проблема** — иначе это не решение.
```

Шкала: `CRITICAL` — ломается UI/данные в штатном сценарии либо публикуется битый артефакт; `HIGH` — воспроизводимый баг,
утечка, регрессия >15%;
`MEDIUM` — несогласованность API/типов/доков, дыра в тестах, отсутствующий гейт; `LOW` — шероховатость DX.

Инфляция серьёзности — худший дефект отчёта. `CRITICAL` без воспроизведения не бывает.

## Команды

```bash
yarn install --frozen-lockfile
yarn lint && yarn type-check && yarn test:run

yarn bench

npx --yes @arethetypeswrong/cli --pack
```

Пакетный менеджер — **Yarn 1.22 Classic**. Замеры размера — gzip и brotli, с указанием версии Node. Временные проекты и
скрипты — в скретчпаде.

## Definition of Done

- [ ] Каждая находка имеет якорь и доказательство.
- [ ] Находки T2/T3 содержат числа с описанием условий замера.
- [ ] Каждое «X медленнее Y» подтверждено тремя прогонами, и эталон Y проверен.
- [ ] Каждое предложенное решение проверено на том сценарии, которым доказана проблема.
- [ ] Гипотезы отделены, их доля ≤ 1/3.
- [ ] Заполнен раздел «Проверено, претензий нет».
- [ ] Нет повторов закрытого в прошлых аудитах без доказанной регрессии.
- [ ] Нет претензий к `gotchas.md` без нового аргумента.
- [ ] Пункты роадмапа не превращены в находки.
- [ ] `ANALYSIS.md` и прошлые аудиты не изменены; исходный код не изменён.
- [ ] Отчёт на русском; идентификаторы и команды — как в коде.

## Чего делать не надо

- Не предлагать миграцию на другой сборщик, менеджер пакетов или тест-раннер.
- Не предлагать рантайм-зависимости: библиотека принципиально однозависимая. Исключение — с расчётом байт и
  обоснованием, почему нельзя без.
- Не пересказывать код — это аудит, а не документация.
- Не выдавать общие места про i18n без привязки к этому коду.
- Не писать «рекомендуется рассмотреть возможность»: либо надо и почему, либо не надо и почему.
