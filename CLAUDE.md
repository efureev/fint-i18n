# CLAUDE.md — оркестратор инструкций репозитория `fint-i18n`

Здесь только неснижаемое ядро. Детальные правила лежат в `.claude/rules/` —
они подгружаются **автоматически**, когда работаешь с подпадающими под них
файлами: триггер — уже чтение, не только правка (`paths` во frontmatter,
глобы от корня репозитория). Справочники, у которых триггер не путь, а
намерение («собрать», «опубликовать», «какая команда»), лежат в `.claude/docs/`
и читаются через `Read` — таблица ниже.

## Что это за проект

**`@feugene/fint-i18n`** — компактная (~2300 строк рантайма) i18n-библиотека для
Vue 3: ленивые блоки переводов с лоадерами, JIT-компиляция шаблонов в функции с
кэшем (без `new Function` — CSP-safe), система хуков как основа расширяемости.
Единственная peer-зависимость — `vue`. Публикуется в npm и GitHub Packages.

Репозиторий **одиночный, не монорепо**. Три слоя исходников, каждый со своим
subpath-экспортом и своей vite-entry:

- `src/core` — рантайм без Vue-компонентных API (только реактивность);
- `src/vue` — plugin, директива `v-t`, `useI18nScope`, inject;
- `src/plugins` — persistence, bridge к `vue-i18n`, hook-logger;
- `playground/` — витрина на GitHub Pages, потребляет **исходники** через алиасы;
- `playground-ssr/` — SSR-витрина (Vue 3 + `renderToString` + гидрация), тоже на исходниках;
- `docs/{en,ru}` — двуязычная документация, 10 зеркальных разделов.

## Жёсткие правила

Вынесены сюда потому, что цена нарушения — тихий баг, сломанный публичный API
или битая публикация, и узнать о них постфактум уже поздно.

1. **Yarn 1.22 Classic.** Не `npm`, не `pnpm`, не Yarn Berry — lockfile
   несовместим. Исключение: `npx --yes publint` / `@arethetypeswrong/cli`.
2. **Слои однонаправлены: `core` ← `vue` ← `plugins`.** `core` не импортирует
   ничего из `vue/` и `plugins/`, а из `vue` тянет **только некомпонентные
   API** — реактивность и утилиты над ref (сейчас это `ref`, `shallowRef`,
   `computed`, `reactive`, `readonly`, `isRef`, `toRaw`; сверить —
   `grep -rn "from 'vue'" src/core/`). Всё, что привязано к жизненному циклу
   компонента (`onUnmounted`, `defineComponent`, директивы), — исключительно
   в `src/vue`.
3. **Новый subpath-экспорт синхронизируется в ШЕСТИ местах** вручную —
   автогенерации нет, пропуск не даёт ошибки сборки:
   `package.json#exports`, `vite.config.ts → build.lib.entry`,
   `tsconfig.json#paths`, `playground/vite.config.ts → resolve.alias`,
   `playground/vitest.config.ts → resolve.alias`,
   `playground-ssr/vite.config.ts → resolve.alias`.
4. **`sideEffects: false`.** Ни один модуль не имеет побочных эффектов на
   верхнем уровне — иначе tree-shaking у потребителя молча вырежет нужное.
5. **Playground работает с ИСХОДНИКАМИ через алиасы, а не со сборкой.**
   Пересобирать библиотеку перед проверкой не нужно. `dist` в `.gitignore`.
6. **Документация двуязычная.** Правка `docs/en/X.md` без синхронной правки
   `docs/ru/X.md` (те же заголовки, та же структура) — незавершённая работа.
7. **Публичный API не ломать без явной необходимости.** Пакет опубликован;
   вместо удаления — deprecation-путь (образец: сеттер `locale.value`,
   делегирующий в `setLocale()` с одноразовым warning).
8. **Не коммитить и не пушить без явной просьбы.**

## Комментарии в коде

Комментарий уместен, только если объясняет то, чего **из кода не видно**:
неочевидный инвариант, грабли, причину неинтуитивного решения. Во всех
остальных случаях — не писать.

Не писать никогда:

- **историю правки.** «Раньше здесь было…», «до 0.5.0 работало так…»,
  «оставлено ради совместимости», «теперь не нужно» — это принадлежит истории
  git и сообщению коммита, а не файлу. Комментарий описывает код в настоящем
  времени, как будто он всегда был таким;
- **пересказ кода.**;
- **подписи к очевидному** — заголовок над списком констант, JSDoc,
  повторяющий имя функции.

Мерило простое: удали комментарий — если ничего не потерялось, он был лишним.
Развёрнутое объяснение уместнее в доке (`docs/**`,`.claude/docs/**`),
куда из кода можно дать ссылку одной строкой.
