# Инструменты для словарей

Пакет поставляет два инструмента командной строки. Они не часть рантайма —
приложение их не импортирует, в бандл они ничего не добавляют. Нужны они потому,
что словари — единственная часть i18n-обвязки, которую не видит система типов:
ключ, переименованный в коде и забытый в `ru.json`, компилируется молча и падает
уже перед пользователем.

| Инструмент | На какой вопрос отвечает |
| --- | --- |
| `fint-i18n-check-messages` | Согласованы ли локали между собой и с кодом? |
| `fint-i18n-codemod-plurals` | Перевод словарей с синтаксиса `\|` (0.4.0) на объекты форм (0.5.0) |

## Запуск

Оба объявлены как `bin`, так что в проекте, который уже зависит от пакета,
устанавливать ничего не нужно:

```bash
npx fint-i18n-check-messages src/i18n/locales --source src
npx fint-i18n-codemod-plurals src/i18n/locales
```

Внутри этого репозитория они же — обычные скрипты:

```bash
yarn check:messages                              # словари playground
node scripts/check-messages.mjs <каталог локалей> # всё остальное
```

Проверки словарей работают на голом Node. Проверкам **по коду** (`--source`)
дополнительно нужен `typescript`, а при наличии `.vue` — ещё и
`@vue/compiler-sfc`. Ни то, ни другое не является зависимостью пакета:
в приложении с `.ts` и `.vue` они уже есть, а тащить компилятор в рантайм-библиотеку
ради проверки словарей — плохой размен. Если пакета нет, инструмент назовёт его,
а не упадёт стеком модулей.

## `fint-i18n-check-messages`

```
fint-i18n-check-messages <каталог локалей> [--source <каталог>]… [--allow <ключ>]… [--strict]
```

Каталог локалей устроен либо как `<локаль>/*.json` (вложенные папки становятся
именами блоков в dot-нотации: `widgets/alpha.json` → `widgets.alpha`), либо как
плоский `<локаль>.json`.

### Совпадение локалей

Каждый ключ обязан быть в каждой локали. Именно эта проверка ловит перевод,
добавленный в пятницу в `en` и так и не продублированный в `ru`.

Намеренная асимметрия — ключ, который действительно принадлежит одной локали, —
объявляется, а не замалчивается:

```bash
npx fint-i18n-check-messages src/i18n/locales --allow legal.usDisclaimer
```

Разные наборы категорий CLDR расхождением **не** считаются. Если у одного и того
же ключа в `en` есть `{one, other}`, а в `ru` — `{one, few, many, other}`, это
норма, и набор форм трактуется как один ключ, а не как ключ на каждую форму.

### Полнота плюральных форм

Набор форм обязан покрывать все категории, которые локаль реально использует.
Русское сообщение с одними `one` и `other` выдаст неверное слово на 2, 3, 22, 104 —
и сообщить об этом рантайм не может: набор с недостающей категорией молча
подставляет запасную форму.

```
✗ неполные наборы плюральных форм (1):
    ru: cart.items — нет форм: few, many
```

Ключи точных значений (`=0`, `=1`) в покрытие не засчитываются и его не ломают.

### Использование ключей

Если задан хотя бы один `--source`, инструмент разбирает код и сверяет найденные
ключи со словарями. Получается два списка.

**Ключи, использованные в коде, но отсутствующие в словарях** — ошибка. Разбор
идёт по AST TypeScript и `@vue/compiler-sfc`, а не регулярками, поэтому `t('…')`
в комментарии или внутри строкового литерала за вызов не принимается. Понимаются:

- `t()`, `te()`, `tm()` и `$t()` — где бы ни находился вызываемый объект
  (`i18n.t`, `scope.t`);
- `v-t="'key'"` и `v-t="{ path: 'key' }"`;
- ключи относительно префиксного скоупа: после
  `useI18nScope(['profile'], { prefix: true })` вызов `t('title')` в этом файле
  проверяется и как `title`, и как `profile.title`, и проходит, если существует
  хотя бы один.

**Ключи, которые есть в словарях, но не найдены в коде** — отчёт, а не ошибка;
печатаются с `?`. Инструмент не видит ключ, собранный в рантайме, поэтому чистый
на вид список «неиспользуемых» — повод прочитать, а не повод удалять. Все
встреченные динамические ключи перечисляются рядом ровно затем, чтобы можно было
оценить полноту списка:

```
! ключи, собранные динамически (2) — из-за них список неиспользуемых неполон:
    src/components/Widget.vue: t(`widgets.${id}.title`…)
```

`tm('common.menu')` помечает использованным всё поддерево — в этом и смысл `tm()`:
компонент не называет отдельные ключи.

Флаг `--strict` делает неиспользуемые ключи тоже ошибкой — разумно, когда
динамических ключей не осталось, и вводит в заблуждение, пока они есть.

### Коды выхода и CI

`0` — всё проверенное прошло. `1` — проверка не прошла либо аргументы негодные.
Больше шагу CI ничего не нужно:

```yaml
- name: Check messages
  run: npx fint-i18n-check-messages src/i18n/locales --source src
```

В этом репозитории тот же шаг запускается как `yarn check:messages`, перед тестами.

### Чего инструмент знать не может

Сказать об этом прямо стоит: проверка, которой доверяют больше, чем она может, —
хуже отсутствия проверки.

- ключ, собранный из переменной, невидим — он сообщается, а не разрешается;
- сообщения, влитые в рантайме через `mergeMessages()`, не лежат ни в одном JSON,
  поэтому ключи к ним читаются как «отсутствующие» и требуют `--allow`;
- читается только JSON. Словари, объявленные в `.ts`, за пределами его области.

## `fint-i18n-codemod-plurals`

```
fint-i18n-codemod-plurals <пути…> [--write] [--locale=ru] [--positional]
```

До 0.5.0 плюральные ветки писались внутри строки сообщения через `|`. Начиная
с 0.5.0 у строки сообщения нет специальных символов вообще, а множественное число
задаётся объектом форм. Этот инструмент выполняет миграцию.

Без `--write` идёт пробный прогон: печатается, что было бы сделано, файлы не
трогаются.

Локаль берётся из имени файла (`ru.json`) или из папки, в которой он лежит
(`locales/ru/common.json`), и больше ниоткуда — путь целиком не сканируется,
потому что `Intl` считает структурно валидным тегом почти любые две-три буквы, и
сегмент `lib` или `tmp` тихо стал бы локалью. Когда раскладка локаль не несёт,
задайте `--locale=`.

### Конвертируется автоматически

Строки с размеченными ветками, где намерение автора однозначно:

```jsonc
// было
{ "files": "one: {n} файл | few: {n} файла | many: {n} файлов | other: {n} файла" }
// стало
{ "files": { "one": "{n} файл", "few": "{n} файла", "many": "{n} файлов", "other": "{n} файла" } }
```

Метки точных значений (`=0:`) сохраняются и ставятся перед именованными
категориями. Если получившийся набор не покрывает категории локали, инструмент об
этом скажет: он конвертирует и предупреждает, а не выдумывает форму.

### Оставляется человеку

Ветки без меток **не** конвертируются — и это центральное решение инструмента.
В синтаксисе 0.4.0 `"Имя | Почта"` и `"{n} файл | {n} файла"` имеют одинаковую
форму. Угадывание между ними ровно тем и было опасно, поэтому кодмод не гадает, а
сообщает:

```
? table.header  [positional]
    "Имя | Почта"
    Похоже на обычный текст: веток 2, категорий у "ru" — 4, плейсхолдера
    счётчика нет. Скорее всего, оставить как есть.
```

Там, где строка на формы всё-таки похожа — есть плейсхолдер `{n}`/`{count}` либо
число веток совпало с числом категорий локали, — предлагается готовый объект,
который можно вставить. Флаг `--positional` принимает все такие предложения
разом; пользоваться им стоит только после прочтения пробного прогона.

Ещё два случая сообщаются, а не конвертируются: частично размеченные ветки
(неразмеченные в 0.4.0 были недостижимы, так что намерение приходится
восстанавливать) и строки с `||`, которые раньше выводились как один `|`, а
теперь выведутся как два.

### После миграции

Прогоните по результату проверку. Кодмод конвертирует то, что может доказать;
проверка говорит, полон ли итог:

```bash
npx fint-i18n-codemod-plurals src/i18n/locales --write
npx fint-i18n-check-messages src/i18n/locales --source src
```
