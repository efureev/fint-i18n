# Devtools

Инструмент отладки рантайма: какие блоки загружены и кем используются, почему
ключ не нашёлся, что произошло между двумя переключениями локали.

Ядро о нём не знает. Всё состояние собирается из публичного API, хуков и обёрток
над методами инстанса, поэтому в самой библиотеке под devtools нет ни байта —
и в приложении их тоже не будет, если подключать его так, как описано ниже.

## Что это и чем не является

Devtools отвечает на вопросы о **запущенном приложении**. Вопросы о словарях как
о файлах — «согласованы ли локали», «полон ли набор форм», «какой ключ больше не
используется» — закрывает [`check-messages`](./tooling.md): у статической
проверки есть доступ ко всем словарям сразу, у рантайма — только к загруженному.

## Подключение

Единственная гарантия «0 байт в проде» — отдельный subpath плюс динамический
импорт под условием сборки:

```typescript
import { createFintI18n } from '@feugene/fint-i18n/core'

const plugins = import.meta.env.DEV
  ? [(await import('@feugene/fint-i18n/devtools')).createDevtools()]
  : []

const i18n = createFintI18n({ locale: 'en', plugins })
```

Статический импорт `@feugene/fint-i18n/devtools` в общем файле сведёт эту
гарантию на нет: сборщик увидит его безусловно и положит в бандл.

Подключать через `plugins` предпочтительнее, чем передавать готовый инстанс:
`install` тогда вызывается в конструкторе — до первых загрузок и до того, как
`installI18n` снимет копию `t` в `$t`, — и история получается полной. Второй
способ поддерживается, но часть событий до подключения потеряна:

```typescript
const devtools = createDevtools(i18n)
```

## API

### `createDevtools(i18n?, options?)`

```typescript
interface DevtoolsOptions {
  name?: string        // имя инстанса в мосте, по умолчанию 'i18n'
  eventLimit?: number  // размер ленты, по умолчанию 200
  bridge?: boolean     // false — не публиковать в window
}
```

Возвращает объект, реализующий `FintI18nPlugin`, поэтому `dispose()` инстанса
отцепляет его сам — через `uninstall`.

### `snapshot()`

Состояние на момент вызова: текущая и запасная локали, известные и доступные
локали, зарегистрированные и загруженные блоки, счётчики использований,
длительности загрузок, промахи ключей, срабатывания фолбэка, предупреждения,
опции инстанса, список плагинов и число скомпилированных ключей по локалям.

Поле `version` — версия пакета. Она нужна не для красоты: ключ инъекции —
`Symbol.for('FintI18n')`, то есть глобальный, и две разные версии пакета в одном
рантайме его делят. Расхождение версий в двух снимках — это и есть диагноз.

После `dispose()` вызов бросает: devtools не удерживает освобождённый инстанс.

### `events`, `subscribe(listener)`, `clearEvents()`

Лента событий, новые в конце. Кольцевой буфер: старые вытесняются по достижении
`eventLimit`.

Промахи ключей и срабатывания фолбэка **дедуплицируются**: в ленту идёт только
первое появление пары «локаль + ключ», счётчик — в снимке. Иначе непереведённый
ключ на активной странице заполнил бы ленту собой: `onMissingKey` приходит заново
после каждой загрузки блока, а `onFallback` — на каждый вызов `t()`.

### `detach()`

Снимает подписки и возвращает исходные ссылки обёрнутым методам, не трогая сам
инстанс. Нужен, когда панель закрывают, а приложение продолжает работать.

## Мост в window

При подключении devtools публикует себя в `window.__FINT_I18N_DEVTOOLS__` —
отсюда с ним работают консоль и e2e-тесты. Инстансы хранятся через `WeakRef`,
поэтому мост ничего не удерживает; на сервере (`window` отсутствует) не делает
ничего.

```typescript
__FINT_I18N_DEVTOOLS__.list()              // имена живых инстансов
__FINT_I18N_DEVTOOLS__.snapshot()          // снимок первого (или по имени)
__FINT_I18N_DEVTOOLS__.events()
await __FINT_I18N_DEVTOOLS__.waitFor('auth', 'ru')
```

`waitFor(block, locale?, { name?, timeout? })` — то, ради чего мост нужен в
тестах: дождаться загрузки блока, а не текста на экране. Уже загруженный блок
резолвится сразу, по истечении `timeout` (по умолчанию 5000 мс) промис
отклоняется.

## Чего devtools не видит

Сказать об этом прямо стоит: инструмент, которому доверяют больше, чем он может,
хуже отсутствия инструмента.

- **Вызовы `t()` не считаются.** Подписка на `onTranslate` стоит +17 % к каждому
  переводу, поэтому по умолчанию её нет. Промахи и фолбэки видны через
  собственные хуки и ничего не стоят.
- **Предупреждения `Intl` и неполные наборы плюральных форм не попадают в
  снимок.** Их кэши модульные, до инстанса оттуда не дотянуться, и в `onWarning`
  они не идут — только в консоль.
- **Счётчик использований растёт только от `useI18nScope`.** Компонент, который
  просто зовёт `t('common.x')`, блок не регистрирует, и в счётчике его нет.
- **История до подключения потеряна**, если devtools передан готовому инстансу,
  а не через `plugins`.
