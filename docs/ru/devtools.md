# Devtools

Инструмент отладки рантайма: какие блоки загружены и кем используются, почему
ключ не нашёлся, что произошло между двумя переключениями локали.

Ядро о нём не знает. Всё состояние собирается из публичного API, хуков и обёрток
над методами инстанса, поэтому в самой библиотеке под devtools нет ни байта —
и в приложении их тоже не будет, если подключать его так, как описано ниже.

## Что это и чем не является

Devtools отвечает на вопросы о **запущенном приложении**. Вопросы о словарях как
о файлах — «согласованы ли локали», «полон ли набор форм», «какой ключ больше не
используется» — закрывает [`check-messages`](./tooling.md): у статической
проверки есть доступ ко всем словарям сразу, у рантайма — только к загруженному.

## Подключение

Единственная гарантия «0 байт в проде» — отдельный subpath плюс динамический
импорт под условием сборки:

```typescript
import { createFintI18n } from '@feugene/fint-i18n/core'

const plugins = import.meta.env.DEV
  ? [(await import('@feugene/fint-i18n/devtools')).createDevtools()]
  : []

const i18n = createFintI18n({ locale: 'en', plugins })
```

Статический импорт `@feugene/fint-i18n/devtools` в общем файле сведёт эту
гарантию на нет: сборщик увидит его безусловно и положит в бандл.

Подключать через `plugins` предпочтительнее, чем передавать готовый инстанс:
`install` тогда вызывается в конструкторе — до первых загрузок и до того, как
`installI18n` снимет копию `t` в `$t`, — и история получается полной. Второй
способ поддерживается, но часть событий до подключения потеряна:

```typescript
const devtools = createDevtools(i18n)
```

## API

### `createDevtools(i18n?, options?)`

```typescript
interface DevtoolsOptions {
  name?: string        // имя инстанса в мосте, по умолчанию 'i18n'
  eventLimit?: number  // размер ленты, по умолчанию 200
  bridge?: boolean     // false — не публиковать в window
}
```

Возвращает объект, реализующий `FintI18nPlugin`, поэтому `dispose()` инстанса
отцепляет его сам — через `uninstall`.

### `snapshot()`

Состояние на момент вызова: текущая и запасная локали, известные и доступные
локали, зарегистрированные и загруженные блоки, счётчики использований,
длительности загрузок, промахи ключей, срабатывания фолбэка, предупреждения,
опции инстанса, список плагинов и число скомпилированных ключей по локалям.

Поле `version` — версия пакета. Она нужна не для красоты: ключ инъекции —
`Symbol.for('FintI18n')`, то есть глобальный, и две разные версии пакета в одном
рантайме его делят. Расхождение версий в двух снимках — это и есть диагноз.

После `dispose()` вызов бросает: devtools не удерживает освобождённый инстанс.

### `events`, `subscribe(listener)`, `clearEvents()`

Лента событий, новые в конце. Кольцевой буфер: старые вытесняются по достижении
`eventLimit`.

Промахи ключей и срабатывания фолбэка **дедуплицируются**: в ленту идёт только
первое появление пары «локаль + ключ», счётчик — в снимке. Иначе непереведённый
ключ на активной странице заполнил бы ленту собой: `onMissingKey` приходит заново
после каждой загрузки блока, а `onFallback` — на каждый вызов `t()`.

### `detach()`

Снимает подписки и возвращает исходные ссылки обёрнутым методам, не трогая сам
инстанс. Нужен, когда панель закрывают, а приложение продолжает работать.

## Панель внутри приложения

`mountDevtoolsOverlay(devtools, options?)` монтирует панель и возвращает функцию
размонтирования. Тело панели грузится динамическим `import()`, поэтому
приложение, которому нужен только снимок в консоли, за UI не платит.

```typescript
const devtools = createDevtools()
const i18n = createFintI18n({ locale: 'en', plugins: [devtools] })

const unmount = await mountDevtoolsOverlay(devtools, {
  position: 'bottom-right',  // и три остальных угла
  hotkey: 'alt+i',           // false — не вешать обработчик вовсе
  collapsed: false,          // true — начать значком
})
```

Вкладки: **locales**, **blocks**, **dictionary**, **missing**, **events**,
**caches**. Кнопка `↓` в шапке выгружает снимок и ленту одним JSON — его удобно
приложить к багрепорту.

Панель живёт в собственном Vue-приложении и в Shadow DOM, а не в дереве
приложения. Причин две, и обе неустранимы иначе: в дереве хозяина она попала бы
в его же Vue Devtools и в его счётчики `useI18nScope`, а без теневого корня её
разнесли бы стили приложения. Своего CSS импортировать не нужно — стили едут
внутри.

Без `document` (сервер) `mountDevtoolsOverlay` возвращает функцию, которая
ничего не делает, поэтому вызов безопасен и в универсальном коде. В
SSR-приложении панель монтируют **после гидрации** — до неё снимок показал бы
состояние, которого у приложения ещё нет.

### Положение и размер панели

Панель таскается за шапку (в местах, где нет кнопок), тянется за правый нижний
угол и запоминает, где её оставили.

- **Перетаскивание** — за шапку. Панель не выпускается за пределы окна целиком,
  а не «оставляя уголок»: наполовину вывалившаяся панель бесполезна ровно так
  же, как улетевшая.
- **Прилипание к краю** — автоматическое, на отпускании. Ближе 24 px к краю
  панель встаёт на отступ 16 px от него. Магнита во время движения нет
  намеренно: он дёргает панель под курсором и мешает ставить её точно. Пока
  прилипание сработает, рамка панели подсвечивается.
- **Размер** — правый нижний угол: он помечен штриховкой, сам жест нативный
  (`resize: both`). От 320×200 и не больше окна.
- **Сброс** — двойной клик по шапке: панель возвращается в угол из опций и к
  исходному размеру, запись стирается.
- **Свёрнутый значок** всегда сидит в углу из опций и за размером окна не
  следит: сохранённое положение посчитано для панели, у значка такого размера
  нет, и по нему он уезжал бы под край окна.

Положение хранится **привязкой к краю с отступом**, а не координатами. Отсюда
главное свойство: когда край окна двигается, панель едет за ним — прижатая к
правому краю остаётся прижатой и на узком экране. По той же причине запись
переносима между экранами разного размера.

При восстановлении положение и размер прогоняются через ограничение по текущему
окну. Без этого запись, сделанная на большом мониторе, оставила бы панель за
экраном — и достать её было бы нечем.

```typescript
await mountDevtoolsOverlay(devtools, {
  storage: sessionStorage,  // по умолчанию localStorage
})

await mountDevtoolsOverlay(devtools, { storage: false })  // не запоминать вовсе
```

Ключ хранения — `fint-i18n-devtools:layout`. Битая или неполная запись не
применяется и удаляется: панель не должна спотыкаться о неё при каждом открытии.

### Язык самой панели

Подписи панели переведены на английский и русский. По умолчанию панель следует
за локалью приложения: переключили язык — переключилась и она. Локаль, которой у
панели нет, сводится к английскому (`ru-RU` при этом доезжает до `ru`).

```typescript
await mountDevtoolsOverlay(devtools, { locale: 'ru' })  // зафиксировать
await mountDevtoolsOverlay(devtools)                    // следовать за приложением
```

Переводы живут на **отдельном инстансе** `FintI18n`, а не на инстансе
приложения, и это не перестраховка. Общий инстанс означал бы, что панель
попадает в собственные наблюдения: свой блок в таблице блоков, свои ключи в
словаре и в топе метрик. Хуже того, в режимах `keys` и `pseudo` панель перевела
бы **сама себя** — вкладки стали бы `tabs.blocks` или `[ƀļöçķš]`, и инструмент
диагностики сломался бы ровно тогда, когда он нужен.

Побочная польза: это работающая демонстрация двух независимых инстансов в одном
рантайме — и панель i18n-библиотеки, локализованная этой же библиотекой, вплоть
до плюральных форм в собственных сообщениях.

Переводится только то, что панель пишет сама. Значения из рантайма — имена
блоков и локалей, типы событий, коды предупреждений, тексты ошибок — остаются
как есть: их ищут в документации и в исходниках, а не в переводе.

## Действия и режимы

`devtools.actions` — write-операции, все через публичный API инстанса:

| Действие | Что делает |
| :--- | :--- |
| `setLocale(locale)` | переключить локаль |
| `loadBlock(block, locale?)` | загрузить блок |
| `unloadBlock(block, locale?)` | выгрузить из памяти |
| `reloadBlock(block, locale?)` | выгрузить и загрузить заново — лоадер отработает повторно |
| `patchMessage(locale, key, value)` | правка перевода на лету; ключ в dot-нотации, как в `t()` |
| `clearCompiled(locale?)` | инвалидировать кэш компиляции |
| `clearFormatterCache()` / `clearPluralCache()` | сбросить кэши `Intl` |
| `missingKeysPatch()` | заготовка словаря из промахов — готовый JSON-патч по локалям |

`reloadBlock` сам разбирается с восходящим резолвингом: если `pages.articles`
грузился лоадером `pages`, выгружен будет `pages` — иначе повторная загрузка
ничего бы не сделала.

`patchMessage` идёт через `mergeMessages`, поэтому правка перерисовывает **всё**,
что показывает это сообщение, включая компоненты, получившие его из кэша
компиляции.

### Режим вывода `t()`

```typescript
devtools.setMode('keys')    // t() возвращает ключ
devtools.setMode('pseudo')  // [Ĥéļļö, Åļéx!·····]
devtools.setMode('off')     // как было, байт в байт
```

**`keys`** отвечает на вопрос «откуда взялась эта строка»: на экране остаются
ключи, и найти нужный в словаре можно не гадая.

**`pseudo`** отвечает сразу на два: какая строка **не** прошла через `t()` — она
останется без акцентов, — и что поедет в вёрстке от перевода длиннее
английского. Строка растягивается примерно на 30 %, как растут немецкий и
финский.

Подписчик `onTranslate` живёт ровно столько, сколько включён режим: каждый
перевод с ним стоит примерно на 17 % дороже. Промах остаётся промахом — `t()`
по-прежнему вернёт сам ключ, а `onMissingKey` сработает.

Переключение режима перерисовывает страницу целиком: словарь оно не меняет,
поэтому devtools инвалидирует кэш компиляции, а его версию `t()` читает на
каждом вызове. Единственное, чего это не достаёт, — компоненты, показывающие
несуществующий ключ: их последний рендер не касался кэша вовсе.

## Расширение Vue Devtools

`connectVueDevtools(app, devtools)` регистрирует плагин в расширении: свой
инспектор, слой ленты и поле в инспекторе компонентов.

```typescript
const app = createApp(App)
app.use(createFintI18nPlugin(i18n))

const devtools = createDevtools(i18n)
await connectVueDevtools(app, devtools)
```

Инспектор повторяет панель — локали, блоки, ключи, промахи, — и это осознанно:
кто живёт в расширении, не должен уходить из него ради i18n. Значение ключа
правится прямо там, как и в панели; набор плюральных форм и сообщение-функция
только на чтение.

Единственное, чего панель дать не может, — **связь с деревом компонентов**. Во
вкладке Components у компонента появляется поле `fint-i18n › blocks`: какие
блоки он попросил через `useI18nScope`. Знание собирается в обёртке над
`registerUsage` — скоуп зовёт его синхронно, до первого `await`, поэтому
контекст компонента ещё доступен.

### Необязательная зависимость

`@vue/devtools-api` объявлен `optional` peer-зависимостью и грузится
динамически. Нет пакета — предупреждение с инструкцией и `false`; панель,
снимок, лента и мост в `window` работают полностью.

```bash
yarn add -D @vue/devtools-api
```

Используется v6-совместимый API плагинов — тот самый, на котором построены
Pinia и Vue Router. В расширении 7 и 8 он поддерживается официально: «Since
v7.3.0, we are fully compatible with the v6 plugin API». Учтите, что в
расширении 7+ ленты плагинов живут не общей вкладкой Timeline, а в меню самого
плагина.

## Метрики

Счётчики вызовов `t()`, топ ключей, длительности загрузок и объём словарей.
Сбор **выключен по умолчанию**: он держит подписчика на `onTranslate` —
единственном хуке, который эмитится на каждый перевод, — а это около 17 % к
стоимости вызова.

```typescript
devtools.metrics.enable({ sampling: 10 })  // считать каждый десятый вызов
devtools.metrics.snapshot()
devtools.metrics.reset()
devtools.metrics.disable()
```

Во вкладке **metrics** сбор включается при её открытии и снимается, как только
вы уходите на другую вкладку или закрываете панель. Пока вкладка открыта, панель
говорит об этой цене прямо в заголовке — иначе о ней забывают ровно до первого
замера производительности.

`sampling: N` считает каждый N-й вызов, а в снимке умножает результат обратно:
`calls` — оценка, `counted` — сколько реально сосчитано. Разменивает точность на
стоимость подписки, и на горячей странице с тысячами вызовов это разумный
размен.

Чего в метриках нет и не будет: **доли попаданий в кэш компиляции**. Снаружи она
не наблюдаема — `t()` не сообщает, откуда взялся результат. Вместо неё есть два
честных числа рядом: сколько ключей скомпилировано и сколько разных ключей
запрашивалось.

## Симулятор лоадеров

Пути отказа — `ready`/`error` у `useI18nScopeSync`, повторы, поведение
`preloadFallback` — иначе проверяются только юнит-тестами: в живом приложении
лоадер не заставить упасть.

```typescript
devtools.simulator.start({
  delay: 400,         // задержка перед ответом лоадера, мс
  failureRate: 1,     // доля отказов, 0..1
  failAttempts: 2,    // отказать первые две попытки, потом пропустить
  blocks: ['auth'],   // по умолчанию — все зарегистрированные блоки
})

devtools.simulator.stop()
```

Во вкладке **blocks** те же три поля и кнопка. Пока симуляция идёт, панель
говорит об этом прямо — иначе через минуту это выглядит как настоящая поломка.

Симулятор ничего не подменяет. Он регистрирует через публичный `addLoaders()`
**дополнительный** лоадер каждому блоку: пустой объект домерживается вникуда,
зато отказ и задержка проходят настоящим путём — через повторы, `onError` и
`ready`/`error` скоупа. Поэтому и сообщения остаются на месте: остановили
симуляцию, загрузили блок — всё как было.

Два ограничения, о которых лучше знать заранее:

- **`failAttempts` виден только у инстанса с опцией `retry`.** Без неё первый
  отказ окончателен, и повторов, которые можно было бы увидеть, просто нет.
- **Снять зарегистрированный лоадер публичным API нельзя**, поэтому выключенная
  симуляция делает его пустышкой, а не удаляет: один лишний вызов, возвращающий
  пустой объект, на каждую загрузку блока до конца жизни инстанса.

## Запись в словари на диске

Замыкает цикл: промах или правка в панели доезжают до словаря на диске, а не
остаются в памяти вкладки. Нужен плагин dev-сервера — отдельный subpath,
подключается в конфиге сборки:

```typescript
// vite.config.ts
import { fintI18nDevtools } from '@feugene/fint-i18n/vite'

export default defineConfig({
  plugins: [
    vue(),
    fintI18nDevtools({ locales: 'src/i18n/locales' }),
  ],
})
```

Каталог локалей — тот же, что понимает
[`fint-i18n-check-messages`](./tooling.md): `<локаль>/<блок>.json` (вложенные
папки дают точки в имени блока) либо плоский `<локаль>.json`.

Плагин объявлен `apply: 'serve'`: эндпоинт пишет файлы, и в прод-сборке его не
существует ни в каком виде.

Панель проверяет наличие плагина при открытии. Есть — в шапке загорается значок
`disk`, и дальше:

- **правка во вкладке `dictionary`** уходит и в память, и в файл;
- во вкладке `missing` появляется кнопка **write stub to dictionaries** —
  недостающие ключи заводятся пустыми строками, готовыми для переводчика.

Заготовка **не затирает существующие значения**. Это важнее, чем кажется: ключ
попадает в список промахов и тогда, когда он в файле есть, а блок просто не был
загружен на момент обращения. Без этой защиты «завести недостающее» стирало бы
переводы.

Форматирование словарей сохраняется — два пробела и перевод строки в конце, как
в остальных файлах.

Клиент доступен и напрямую:

```typescript
if (await devtools.devServer.probe()) {
  await devtools.devServer.write({ ru: { common: { hello: 'Привет' } } }, { overwrite: true })
}
```

## Мост в window

При подключении devtools публикует себя в `window.__FINT_I18N_DEVTOOLS__` —
отсюда с ним работают консоль и e2e-тесты. Инстансы хранятся через `WeakRef`,
поэтому мост ничего не удерживает; на сервере (`window` отсутствует) не делает
ничего.

```typescript
__FINT_I18N_DEVTOOLS__.list()              // имена живых инстансов
__FINT_I18N_DEVTOOLS__.snapshot()          // снимок первого (или по имени)
__FINT_I18N_DEVTOOLS__.events()
await __FINT_I18N_DEVTOOLS__.waitFor('auth', 'ru')
```

`waitFor(block, locale?, { name?, timeout? })` — то, ради чего мост нужен в
тестах: дождаться загрузки блока, а не текста на экране. Уже загруженный блок
резолвится сразу, по истечении `timeout` (по умолчанию 5000 мс) промис
отклоняется.

## Чего devtools не видит

Сказать об этом прямо стоит: инструмент, которому доверяют больше, чем он может,
хуже отсутствия инструмента.

- **Вызовы `t()` не считаются.** Подписка на `onTranslate` стоит +17 % к каждому
  переводу, поэтому по умолчанию её нет. Промахи и фолбэки видны через
  собственные хуки и ничего не стоят.
- **Предупреждения `Intl` и неполные наборы плюральных форм не попадают в
  снимок.** Их кэши модульные, до инстанса оттуда не дотянуться, и в `onWarning`
  они не идут — только в консоль.
- **Счётчик использований растёт только от `useI18nScope`.** Компонент, который
  просто зовёт `t('common.x')`, блок не регистрирует, и в счётчике его нет.
- **История до подключения потеряна**, если devtools передан готовому инстансу,
  а не через `plugins`.
