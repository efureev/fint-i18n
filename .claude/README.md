# `.claude/` — конфигурация ассистента для этого репозитория

```
CLAUDE.md                 # ЗАГРУЖЕН ВСЕГДА: идентичность проекта, жёсткие правила,
                          #   навигация по docs. ~100 строк.
.claude/
  rules/                  # автозагрузка движком по `paths` во frontmatter
                          # после `←` — дословное содержимое `paths`
    library-conventions.md  # ← src/**, vite.config.ts, package.json,
                          #     tsconfig.json, tsconfig.build.json
    playground-conventions.md # ← playground/**, playground-ssr/**
    testing.md              # ← **/__tests__/**, **/*.test.ts, **/*.spec.ts,
                          #     bench/**, vitest.config.ts,
                          #     playground/vitest.config.ts
    docs-conventions.md     # ← docs/**, README.md, README.ru.md
  docs/                   # НЕ автозагружается: читается через Read по таблице в CLAUDE.md
    gotchas.md              # перед сборкой/публикацией/браузером и при необъяснимом
    workspace.md            # команды, карта репо, шпаргалка по публичному API
    git-and-release.md      # коммиты, CI, теги, публикация
  settings.local.json     # локальные разрешения (не редактируется вручную,
                          #   закрыт репозиторным .gitignore)
```

Глобы здесь выписаны дословно: сводка «по смыслу» уже привела бы к правке
frontmatter в сторону нерабочей формы (см. предупреждение про `**` ниже).

В корне лежат ещё три документа с триггером-намерением — они в таблице
`CLAUDE.md`, но не автозагружаются: `ANALYSIS.md` (роадмап и нумерация пунктов
для коммитов), `AUDIT-2026-08.md` (закрытый аудит: запись о проверенном плюс
baseline перфоманса и размера), `AUDIT-PROMPT.md` (ТЗ на новый аудит).

## Модель загрузки

Всегда в контексте — только `CLAUDE.md`. Остальное приходит под задачу, но
**двумя разными механизмами**, и путать их дорого:

1. **`.claude/rules/*.md` — автозагрузка движком.** Claude Code сам подтягивает
   каждый файл из этого каталога. Ключ `paths` во frontmatter сужает загрузку до
   работы с подпадающими файлами; **файл без `paths` сидит в контексте всегда**.
   Это и есть причина, по которой каталог держат маленьким.
   Триггер срабатывает уже на **чтение** файла, не только на правку.
   Глобы матчатся от корня репозитория; для произвольной вложенности нужен `**`
   (`**/*.test.ts`, а не `*.test.ts`).
2. **`.claude/docs/*.md` — обычные файлы.** Движок их не знает; попадают в
   контекст только через `Read`. Сюда идёт то, чей триггер — намерение
   («собрать», «опубликовать», «какая команда»), а не путь: такое через `paths`
   не выражается. Видимость обеспечивает таблица в `CLAUDE.md`.

⚠️ **`@`-импорт в `CLAUDE.md` — не способ сделать что-то ленивым.** Импорты
транзитивны и разворачиваются при старте: `@`-ссылка на индекс не откладывает
загрузку, а гарантирует её. Ссылаться на `docs/*` только обычными путями в
бэктиках.

Риск такой схемы — «не прочитал, потому что не догадался». Он снят тремя
приёмами, и их надо сохранять при доработках:

1. **Триггеры заданы путями файлов, а не темами** — там, где это возможно
   (`paths`). Какой файл я собираюсь открыть, известно раньше, чем сформулирована
   тема.
2. **Неснижаемое ядро осталось inline в `CLAUDE.md`** — факты, чья цена
   пропуска необратима или даёт тихий баг (Yarn Classic, направление зависимостей
   между слоями, 6 точек регистрации subpath'а, `sideEffects: false`,
   зеркальность документации).
3. **Каждый файл правил и доков начинается с блока «Применяется когда / Не нужно /
   Смежное»** — чтобы граница применения читалась и из самого файла.

## Роли слоёв

- **rules** — декларативные инварианты, применимые к **любой** правке, включая
  точечную. Триггер — путь.
- **docs** — те же инварианты, но с триггером-намерением. Формально это те же
  правила; в отдельном каталоге они лежат только потому, что `.claude/rules/`
  автозагружается, а держать их постоянно в контексте не за что.
- **skills / agents** — пока не заведены. Появятся, когда обнаружится
  повторяющаяся многошаговая процедура (кандидаты: «добавить subpath-экспорт» —
  6 точек синхронизации; «добавить секцию в playground»).

## Как поддерживать

- Грабля, стоившая времени → `docs/gotchas.md`. Если цена пропуска
  необратима — ещё и строкой в «Жёсткие правила» `CLAUDE.md`.
- Новая точка синхронизации, новый скрипт → в соответствующее правило
  **и** в `docs/workspace.md`.
- Новое правило с path-триггером → в `rules/` **с `paths` во frontmatter**.
  Без `paths` файл будет висеть в контексте всегда — это регрессия, не мелочь.
- Новый док с триггером-намерением → в `docs/` **и строкой в таблицу
  `CLAUDE.md`**, иначе он невидим.
- Не дублируй содержимое в `CLAUDE.md` — там только ссылка и ядро.
- Проверка после доработок: `/context` → в «Memory files» должны быть только
  `CLAUDE.md` и правила, подпадающие под текущую работу. Всё прочее — ошибка.
