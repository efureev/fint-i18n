# Rules: конвенции витрин

> **Применяется когда:** правишь `playground/**` или `playground-ssr/**` —
> секции демо, словари, лоадеры, uno-конфиг, конфиги vite/vitest витрин.
> **Не нужно:** работа только в `src/**` или `docs/**`.
> **Смежное:** `.claude/docs/gotchas.md` — почему витрина не открывается;
> `.claude/rules/testing.md` — у playground отдельный прогон тестов.

## Как playground видит библиотеку

Через **алиасы на исходники** (`playground/vite.config.ts` →
`resolve.alias` → `../src/...`), а не через `dist`. Пересобирать библиотеку
перед проверкой не нужно — HMR подхватывает правку `src/**` сразу.

Версия пакета в футере приходит из `define: { __FINT_I18N_VERSION__ }` в обоих
конфигах витрины (`vite.config.ts` и `vitest.config.ts`). Тот же токен читает
`src/devtools` — в витрине он резолвится её же define, и значение совпадает:
оба берут версию из корневого `package.json`. В компоненте токен
присваивается локальной константе: в шаблоне `<script setup>` резолвит
незнакомый идентификатор в `_ctx.…`, и подстановка до него не доходит — версия
отрендерится пустой без единой ошибки сборки.

Запуск: `yarn playground` (он же `yarn dev`), порт **3000**.
`base: '/fint-i18n/'` действует и в деве — открывать
**`http://localhost:3000/fint-i18n/`**, на корне будет пусто.

## Роль: playground — исполняемая документация

Каждая секция демонстрирует одну возможность и живёт отдельным компонентом в
`playground/src/components/sections/`:

| Секция | Что показывает |
| --- | --- |
| `BasicSection` | `t()`, параметры, экранирование |
| `DirectiveSection` | `v-t`, модификаторы `.once`/`.preserve` |
| `LazyLoadSection` | ручной `loadBlock` |
| `PartialBlocksSection` | собственный лоадер против восходящего резолвинга (`page.terms` → `page`) |
| `WildcardSection` | `prefix.*` (для `**` в витрине нет достаточно глубокого блока) |
| `FallbackSection` | `fallbackLocale` + `preloadFallback` |
| `ScopeSyncSection` | `useI18nScopeSync` без `<Suspense>` |
| `MemorySection` | reference counting, `unloadUnusedBlocks` |
| `DynamicLoadersSection` | `addLoaders()` в рантайме (блок `announce`) |
| `PluralSection` | формы CLDR, `selectPluralCategory` |
| `FormatSection` | `useI18nFormat()` — `n()`/`d()` |
| `IntrospectionSection` | `te()` и `getAvailableLocales()` |
| `SubtreeSection` | `tm()` — переводы как данные |
| `RetrySection` | опция `retry` и `dispose()` на отдельном инстансе |

Переключатель локали — `components/LocaleSwitcher.vue`, сегментированный контрол.
Состав кнопок берётся из `getAvailableLocales()`, подписи — из `Intl.DisplayNames`
на самом языке, так что новая локаль появляется в шапке сама, без правки UI.

Новая возможность библиотеки без секции в playground — работа наполовину:
это единственное место, где поведение проверяется глазами.

Подключение секции — две точки: файл в `sections/` и импорт + вставка в
`playground/src/Playground.vue`.

Карточку, надзаголовок, заголовок и описание даёт `components/PlaygroundSection.vue`
— своей разметки у секции быть не должно. Тексты передаются **уже
переведёнными** (`:eyebrow="t('ui.sections.x.eyebrow')"`), а не ключами: ключ,
собранный внутри компонента из пропа, стал бы для `check-messages` динамическим
и вывел бы весь `ui.sections.*` из-под проверки. Бейдж справа от заголовка —
слот `#aside`, остальное содержимое — слот по умолчанию.

Забытый импорт `PlaygroundSection` не роняет ни сборку, ни `t()`: Vue рендерит
неизвестный компонент пустотой и ограничивается предупреждением, секция просто
исчезает со страницы. От этого страхует тест «renders every section, numbered
without gaps» — он сверяет номера надзаголовков с 1…N.

## Словари и лоадеры

- JSON-словари: `playground/src/i18n/locales/{en,ru,es}/**`. Все три локали
  обязательны — расхождение ключей ломает демо fallback'а и роняет
  `yarn check:messages`. Наборы категорий CLDR у них разные (en — две, es — три,
  ru — четыре), и это норма, а не расхождение: проверка это учитывает.
- Регистрация: `playground/src/i18n/messages/{en,ru,es}.ts` (по локали, типизировано
  `LocaleLoaderCollection`), баррель `index.ts` реэкспортит **только именованные
  локали**. Толстый агрегат — `all.ts`, и он **никогда не реэкспортится из
  `index.ts`**: это убило бы per-locale tree-shaking, ради демонстрации которого
  барьер и существует.
- Блок `announce` намеренно **не** зарегистрирован в `en.ts`/`ru.ts`/`es.ts` — он
  добавляется в рантайме в `DynamicLoadersSection`. Не «чинить» это.
- `playground/src/main.ts` держит три закомментированных варианта подключения
  лоадеров (per-locale / один `all` / несколько пакетов) — это документация для
  потребителей, комментарии не удалять.

## Стили

UnoCSS, конфиг `playground/uno.config.ts` (`presetMini` + иконки + типографика
+ веб-шрифты), шорткаты `btn` / `icon-btn`. Дизайн-системы здесь нет —
utility-классы прямо в шаблоне, это нормально.

## Что playground НЕ покрывает

- **ESLint его игнорирует** (`playground/**` в `ignores`) — на линт как на
  страховку не рассчитывать.
- **`yarn type-check` его не проверяет** — `tsconfig.json#include` содержит
  `src`, `bench` и корневые конфиги, но не `playground`. Ошибки типов здесь
  всплывут только на `yarn playground:build`.

## Вторая витрина: `playground-ssr/`

Отдельное приложение, потому что `playground/` статический и едет на GitHub
Pages, а SSR требует сервера.

- Запуск: `yarn playground:ssr` (порт **3100**), прод-путь —
  `yarn playground:ssr:build && yarn playground:ssr:prod`.
- `server.mjs` — на `node:http` без Express: рантайм-зависимостей у пакета нет,
  и заводить их ради витрины незачем.
- Демонстрирует ровно то, чего нет в статической витрине: снимок состояния,
  гидрацию и то, что после неё клиент **не ходит в сеть**. Доказательство —
  счётчик вызовов лоадеров, привязанный к инстансу (не к модулю: на сервере
  модульный счётчик копился бы между запросами).
- `?locale=ru|en` и `?hydrate=0` — переключатели для сравнения руками.
- Отложенная секция (`LazyBlockDemo` → `LazyBlockPanel`, блок `promo`) —
  обратная сторона того же счётчика: компонент под `v-if`, поэтому лоадер
  `defineAsyncComponent` не срабатывает на сервере и блока нет ни в разметке,
  ни в снимке. `suspensible: false` и `useI18nScopeSync` здесь не вкусовщина:
  Suspense из `App.vue` к моменту клика уже разрешён, и асинхронная зависимость
  вернула бы его в pending, мигнув фолбэком на всю страницу.
- Стили — обычный CSS в `index.html`, без UnoCSS: витрина про i18n, а не про
  сборку стилей под SSR.

Два правила, которые тут легко нарушить и получить расхождение гидрации:

1. **Данные, известные только после рендера** (размер снимка, состав блоков),
   заполняются в `onMounted`, а не при рендере — иначе сервер и клиент выдадут
   разное.
2. **Даты**: момент времени едет в полезной нагрузке, а не берётся из
   `Date.now()` с обеих сторон, и у каждого вызова `d()` явный `timeZone` —
   пояс сервера не совпадает с браузерным.

Тесты обеих витрин гоняет один конфиг `playground/vitest.config.ts`
(`include` покрывает оба каталога) — третий гейт в CI ради тех же проверок
не нужен.
