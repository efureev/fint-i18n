# Rules: документация

> **Применяется когда:** правишь `docs/**` или любой `README*.md`.
> **Не нужно:** правка только кода без изменения публичного поведения.
> **Смежное:** `.claude/rules/library-conventions.md` — источник истины по API.

## Зеркальность en/ru — жёсткий инвариант

`docs/en/` и `docs/ru/` содержат **одни и те же 11 разделов** с одинаковой
структурой заголовков (сверяется построчно по `^#`):

```
api.md            defining-messages.md   installation.md   plugins.md
blocks.md         bundle-analysis.md     usage.md          authoring-localization-packages.md
ssr.md            tooling.md             devtools.md
```

Правка одного языка без второго — незавершённая работа. То же для пары
`README.md` ↔ `README.ru.md`.

Практика: править оба файла **в одном проходе**, а не «потом переведу».
Проверка симметрии:

```bash
diff <(grep '^#' docs/en/blocks.md) <(grep '^#' docs/ru/blocks.md) | head
```

Расхождение уровней/порядка заголовков ломает якорные ссылки между разделами
и из README.

## Что где описывается

| Файл | Содержание |
| --- | --- |
| `installation.md` | установка, `createFintI18n`, `installI18n` / `createFintI18nPlugin`, опции |
| `defining-messages.md` | форматы JSON, лоадеры, динамический merge |
| `authoring-localization-packages.md` | контракт per-locale экспорта для пакетов-доноров |
| `usage.md` | `t()`, `$t`, `v-t`, скоупы |
| `api.md` | полная справка по методам, композаблам, типам |
| `plugins.md` | хуки и встроенные плагины |
| `blocks.md` | блоки, резолвинг, wildcard, память |
| `bundle-analysis.md` | бенчмарки и анализ `dist` |
| `ssr.md` | снимок состояния сервером, гидрация на клиенте, контракт и ограничения |
| `tooling.md` | CLI-инструменты: проверка словарей (`check-messages`) и кодмод плюрализации |
| `devtools.md` | отладка рантайма: снимок состояния, лента событий, мост в `window` |

Новая публичная возможность → раздел в `api.md` (оба языка) **и** упоминание в
профильном разделе. Новый файл документации → ссылка из обоих README в блоке
«Documentation» / «Документация».

## Стиль

- Примеры кода — рабочие: импорты из реальных subpath'ов
  (`@feugene/fint-i18n/core`, `/vue`, `/plugins`), а не из корня «для краткости».
- Каждое утверждение о поведении проверяется по коду `src/**`, а не по памяти:
  документация уже расходилась с реализацией — и не раз. Примеры из доков
  исполняются тестом `src/core/__tests__/doc-examples.test.ts`; новый пример
  стоит добавлять туда же.
- Ограничения и подводные камни документируются явно (образец: «выгружать нужно
  по имени фактически загруженного родительского блока»). Умолчание о грабле
  дороже лишнего абзаца.
- ESLint файлы документации не проверяет — за корректность блоков кода отвечает
  автор.
