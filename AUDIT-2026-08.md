## 1. Итог

Аудит закрыт: из 30 находок 27 исправлены, три сняты — F-25 как ложная (ошибка самого аудита), F-14 и F-30 решением
владельца. Открытых находок нет.

Ядро библиотеки — блоки, ленивая загрузка, кэш компиляции, слои, tree-shaking — подтверждено как здоровое:
компилированный кэш обходит vue-прокси на горячем пути, форматтеры и SSR-хелперы не протекают в бандл тем, кто их не
импортирует, порядок CLDR-категорий корректен для всех проверенных локалей. Полный перечень проверенного — в разделе 2.

Главной находкой была плюрализация 0.4.0, тихо портившая словари: она заменена представлением формами-объектом, где ни
один символ строки не имеет специального значения. Плюральный вызов при этом стал быстрее исходного в 3–4 раза за счёт
мемоизации выбора ветки.

**Три доказательства самого аудита при повторной проверке не устояли** — все три разобраны в оговорках шапки: F-13
(предложенный FIFO не решал измеренную проблему), F-23 (утверждение «медленнее `startsWith`» не воспроизвелось), F-25
(вывод сделан из манифеста без прогона `npm pack`). Ещё две проекции замер не подтвердил — разделы 3.3 и 4.3.

Дальнейшая работа лежит не в находках, а в роадмапе — [`ANALYSIS.md`](./ANALYSIS.md).

## 2. Проверено, претензий нет

- **Tree-shaking работает фактически.** В сценарий «core + `t()`» не попадает ни одного упоминания `NumberFormat`/
  `DateTimeFormat`; в сценарий «vue + scope» — ни одного упоминания плагинов и `localStorage`. Заявление
  `sideEffects: false`
  подтверждено сборкой, а не декларацией.
- **Компилированный кэш успешно обходит vue-прокси на горячем пути.** Глубокое чтение `readonly(reactive())` стоит 889
  нс, `reactive()` — 154 нс, plain — 5 нс;
  `t()` при попадании в кэш укладывается в 51 нс, то есть прокси на этом пути не участвует. Архитектурное решение
  оправдано замером.
- **Реактивность переживает `unloadBlock` + повторную загрузку.** Отрисованный компонент показывает `value` до выгрузки
  и `value` после перезагрузки; висящей зависимости нет.
- **Плюрализация применяет правила локали сообщения, а не текущей.** Сообщение, разрешённое через `fallbackLocale: 'ru'`
  при текущей `en`, даёт «3 товара». Один и тот же блок в двух локалях сохраняет свои правила; выгрузка и повторная
  загрузка их не путают.
- **Канонический порядок CLDR-категорий корректен** для `en`, `ru`, `pl`, `ar`,
  `cy`, `ja` — включая локали с `zero`/`two`. Решение задавать порядок константой, а не брать из `resolvedOptions()`,
  подтверждено.
- **Предупреждение о невалидном теге локали печатается один раз** — кэш правил пишется и в ветке отката, повторные
  компиляции молчат.
- **Пустая строка-локаль (умолчание `fallbackLocale`) до компилятора не доходит**
  и потому не приводит к молчаливому применению английских правил.
- **Экранирование `||` работает**, в том числе внутри плюральных веток.
- **Приоритет `count` над `n` корректен**, включая `count: undefined`.
- **Реентрантный `setLocale` из подписчика `onLocaleChange`** приходит к верной итоговой локали.
- **Стоимость `MessageKeys<S>` для tsc несущественна.** 7 488 → 40 406 instantiations при росте схемы 0 → 5 000 ключей,
  время компиляции 0.27–0.29 с, память без роста. Подозрение из ТЗ не подтвердилось.
- **Аллокация `{key, params, result}` в `t()` не является проблемой.** Полный
  `t()` — 51.5 нс против 25.5 нс у скомпилированной функции; синтетическая стоимость литерала — 3.8 нс, `Map.get` по
  пустой карте — 4.6 нс. Ломать контракт хука ради этого не нужно. (Оговорка: изолированный замер литерала может быть
  занижен escape-анализом, поэтому 3.8 нс — нижняя граница.)
- **Кэш форматтеров оправдан:** попадание 74.9 нс против 2 339.7 нс на конструирование — 31×.
- **`publint --pack npm` проходит чисто.**
- **`arethetypeswrong`** воспроизводит ровно известный дефект (extensionless импорты в баррелях `.d.ts` не резолвятся
  под node16-ESM) — новых проблем типизации пакета не добавилось; ESM-only падения под node10/require — by design.
- **Симметрия `docs/en` ↔ `docs/ru`** по составу и уровням заголовков сохранена во всех восьми парах, что были на
  v0.4.0. Разделов с тех пор десять — `ssr.md` и `tooling.md` этой проверкой не покрыты.
- **Все механические гейты зелёные:** `lint`, `type-check`, 127 тестов, `build`,
  `playground:build`.

## 3. Перфоманс: измерения

Node v26.6.0, darwin 25.5.0. Прогрев — 10% итераций, затем 1–2 млн итераций на замер. Числа воспроизводятся между
прогонами в пределах ~2%.

### 3.1 Горячий путь `t()`

| Операция                                           | нс/оп | M оп/с |
|----------------------------------------------------|------:|-------:|
| скомпилированная функция напрямую (нижняя граница) |  25.5 |  39.18 |
| `i18n.t()` с параметрами                           |  51.5 |  19.42 |
| `i18n.t()` без параметров (статичное сообщение)    |  17.6 |  56.97 |
| `i18n.t()` с одним подписчиком `onTranslate`       |  60.3 |  16.57 |

Накладные расходы `t()` поверх скомпилированной функции — ~26 нс; из них синтетически: литерал полезной нагрузки 3.8 нс,
`Map.get` 4.6 нс,
`Array.slice()` одного элемента 5.4 нс. Точная атрибуция невозможна без правки исходников (запрещена условиями аудита),
поэтому приведена декомпозиция, а не разложение до последнего наносекунда.

### 3.2 Плюрализация

После перехода на формы-объект и мемоизацию выбора ветки:

| Операция                                   |       до |       после |
|--------------------------------------------|---------:|------------:|
| `t()` плюральный, `ru`                     | 192.8 нс | **61.8 нс** |
| `t()` не-плюральный, та же форма сообщения |  41.3 нс |     36.6 нс |
| `Intl.PluralRules.select()` отдельно       | 157.5 нс |    156.9 нс |

Бенч `yarn bench` подтверждает независимо: `i18n.t() warm cached lookup, plural`
вырос с 4.81 до 20.05 M оп/с (**4.2×**). Проекция была ~45–50 нс — фактические 61.8 нс близки к ней. `select()` теперь
вызывается один раз на значение счётчика, а не на каждый рендер.

### 3.3 Стоимость инвалидации и загрузки блока

| Скомпилированных ключей в локали |        до | после ленивой компиляции | после индекса по корню |
|---------------------------------:|----------:|-------------------------:|-----------------------:|
|                              500 |  46.4 мкс |                 31.0 мкс |           **19.0 мкс** |
|                            2 500 | 160.0 мкс |                 74.3 мкс |           **19.3 мкс** |
|                           10 000 | 658.1 мкс |                427.0 мкс |           **18.1 мкс** |

Линейность по размеру словаря исчезла полностью: инвалидация обходит ключи одного корневого блока, а не всей локали. На
словаре в 10k ключей это 23.6×.

```
mergeMessages блока из 5000 ключей:  было 5.35 мс → стало 3.75 мс
первый t() после загрузки:           было 0.0073 мс → стало 0.0158 мс
```

**Проекция не подтвердилась.** Рекомендуя удаление жадной прекомпиляции, я оценивал стоимость `mergeMessages` 5000
ключей как «~0.3 мс» — фактически 3.75 мс. Ошибка в атрибуции: почти вся оставшаяся стоимость — это `deepMerge`
в `reactive({})`, то есть создание vue-прокси на каждый узел (см. 3.4), а не компиляция. Сокращение на порядок здесь
потребует работы с реактивностью.

### 3.4 Реактивность

| Чтение по глубине 3    | нс/оп |
|------------------------|------:|
| plain object           |   5.0 |
| `reactive()`           | 154.5 |
| `readonly(reactive())` | 889.2 |

Публичный `messages` — `readonly(reactive())`, то есть потребительский код, итерирующий словарь (как debug-панель
playground), платит ~889 нс за глубокое чтение. На горячий путь `t()` это не влияет — см. раздел 2.

### 3.5 Развёртка wildcard и форматтеры

`expandPattern`, 1000 зарегистрированных имён, по три прогона на форму (результаты вариантов сверены на идентичность до
замеров):

| Форма данных и паттерн                 | посимвольно (было) | `startsWith` (стало) | сортировка + бинарный поиск |
|----------------------------------------|-------------------:|---------------------:|----------------------------:|
| плоская, `widgets.*`, 500 совпадений   |              7 843 |                8 840 |                       7 445 |
| плоская, `pages.**`, 500 совпадений    |              6 298 |                5 702 |                       4 846 |
| плоская, `nothing.*`, 0 совпадений     |              1 879 |                1 759 |                      **29** |
| широкая, `root7.*`, 20 из 1000         |              7 387 |                6 344 |                     **345** |
| общий длинный префикс, 1000 совпадений |             68 840 |               62 133 |                      68 615 |

Бинарный поиск по отсортированному массиву выигрывает на разреженных выборках в 20–64 раза, но требует сортировки при
каждом `add()`: 59 мкс на 1000 имён против ~6 мкс на линейный проход. Точка безубыточности — около десяти разных
паттернов на один `addLoaders()`; реальные приложения используют единицы, поэтому вариант отклонён.

| Операция                     |   нс/оп |
|------------------------------|--------:|
| `getNumberFormat` из кэша    |    74.9 |
| `new Intl.NumberFormat(...)` | 2 339.7 |
| `Intl.NumberFormat.format()` |   213.7 |

Ключ кэша строится конкатенацией и стоит ~75 нс — это 26% полной стоимости форматирования (75 + 214). Для таблиц с
сотнями чисел заметно, но трогать это стоит только с замером: путь уже не деградирует, а всякая «оптимизация» ключа
рискует повторить историю F-23.

### 4.3 Цена изменений относительно 0.3.0

ожиданием и фактом упрётся в CI.

## 5. Приложение

### 5.1 Команды воспроизведения

```bash
yarn install --frozen-lockfile
yarn lint && yarn type-check && yarn test:run && yarn build
yarn playground:build
npx --yes publint --pack npm
npx --yes @arethetypeswrong/cli --pack
yarn bench
yarn test:coverage:package
```

Непокрытые публичные API (в первой редакции все восемь давали 0; на 0.7.0 нулевых не осталось —
последним закрыт `preloadFallback`):

```bash
for s in useI18nScopeSync dispose addLoaders unloadUnusedBlocks \
         unloadBlock getSSRProps preloadFallback getKnownLocales; do
  printf "%-22s %s\n" "$s" "$(grep -rho "$s" src --include='*.test.ts' | wc -l)"
done
```

Замер размера (каждый сценарий — отдельной сборкой, `vue` во external), база для сравнения:

```bash
git archive a85a539 | tar -x -C "$BASE"   # v0.3.0, до плюрализации
```
